# Telegram-тренажёр немецкой лексики

Приватный Telegram-бот для двух независимых учеников: интервальные повторения,
короткие push-сессии, длинная тренировка по запросу, объяснения преподавателя
OpenAI и планировщик-куратор. Точные совпадения проверяются локально;
несовпавшие ответы, включая обычные варианты выбора, проверяет отдельный
LLM-grader до изменения интервального расписания.

PostgreSQL — единственный источник данных. CSV в `data/` используются только
для импорта и экспорта колод.

## Локальный запуск

Требуются Python 3.12 через `uv`, Docker/colima и Telegram bot token.

```bash
docker compose up -d
uv sync --frozen
uv run python cli.py user bootstrap --owner-chat-id <telegram_chat_id>
uv run python cli.py sync
uv run python -m bot
```

Бот явно загружает `~/.config/wordsbot/env` (другой путь задаётся через
`WORDSBOT_ENV_FILE`). Файл должен иметь права `0600`:

```dotenv
TELEGRAM_BOT_TOKEN=...
DATABASE_URL=postgresql://words_trainer:...@127.0.0.1:55432/words_trainer
OWNER_CHAT_ID=...
SPOUSE_CHAT_ID=...
OPENAI_API_KEY=... # необязательно: drills и pushes работают без него
TUTOR_MODEL=...    # диалоговый преподаватель
CURATOR_MODEL=...  # планировщик фокуса и напоминаний
GRADER_MODEL=...   # необязательно; по умолчанию TUTOR_MODEL
# Укажите актуальные цены каждой реально используемой модели:
TUTOR_INPUT_USD_PER_MILLION=...
TUTOR_OUTPUT_USD_PER_MILLION=...
CURATOR_INPUT_USD_PER_MILLION=...
CURATOR_OUTPUT_USD_PER_MILLION=...
GRADER_INPUT_USD_PER_MILLION=...
GRADER_OUTPUT_USD_PER_MILLION=...
WORDSBOT_BACKUP_DIR=... # необязательно: по умолчанию ~/Library/Application Support/wordsbot/backups
```

## Команды Telegram

- `/practice` — выбор колоды и длинная тренировка;
- `/quick` — пятиминутная тренировка с ответами только кнопками;
- `/context` — свободная практика в новых ситуациях;
- `/contrast verfügbar / zugänglich` — три упражнения на различия двух выражений;
- `/stop` — остановить;
- `/decks` — колоды;
- `/stats` — компактная общая и поколодная статистика с названиями этапов;
- `/howto` (или `/help`) — как работает алгоритм обучения, стадии и интервалы;
- `/issues` — карточки, требующие исправления;
- `/reminders` — личное окно, дни и примерная частота умных напоминаний.

В `/practice` основа тренировки — слова, срок повторения которых уже наступил.
Каждое четвёртое задание отдаётся новому слову, если такие есть; если одна из
очередей пуста, используется другая. Внутри очереди сначала идут ещё не
показанные карточки, затем те, которые показывались давнее всего. При равной
истории повторения упорядочены по сроку, остальные совпадения разрешаются
случайно. Выбор идёт по всей колоде. История показов и чередование сохраняются
между запусками, включая задания, оставленные без ответа.

Push открывает короткую сессию из пяти заданий. Зрелые слова требуют ввода
текста; кнопки используются только там, где упражнение действительно имеет
варианты. Язык ответа указан в задании. Точное совпадение с
разрешённым вариантом проверяется локально. Несовпавший ответ получает статус
«Проверяю…» и передаётся отдельному grader-у без истории и инструментов. Только
после проверки бот решает, нужно ли менять расписание повторений.
При ошибке API задача остаётся открытой: ответ можно исправить, отправить
на повторную проверку или пропустить без оценки. Кнопка «Показать ответ и
пропустить» также доступна в заданиях со свободным вводом.

### Как учить близкие слова

Подходящий по смыслу и грамматике синоним засчитывается как правильный ответ.
Бот объясняет различие и показывает пример изучаемого слова. Его интервал
пока не растёт: ответ другим выражением не доказывает, что это слово запомнилось.
В этой сессии карточка больше не повторяется; в следующей бот предпочитает
проверить её в контексте. После успешного воспроизведения возвращается обычный
подбор заданий.

После принятого альтернативного ответа на изучаемом языке можно нажать
«Различия · 3 задания» или продолжить обычную тренировку. Команда
`/contrast первое выражение / второе выражение` запускает такую же отдельную
сессию; первое выражение должно быть активной карточкой ученика.

Сначала бот кратко объясняет употребление обоих выражений с примерами, затем
даёт три ситуации. В каждой нужно выбрать «только первое», «только второе»
или «оба подходят». После ответа видны объяснение и полная фраза-пример.
Задания и ключи проверяет отдельный вызов модели до показа; варианты затем
проверяются локально по этому ключу. Если честного различия нет, бот должен
признавать оба варианта. Тренировка различий заменяет текущую сессию и
не меняет интервалы слов. После неё можно вернуться через `/practice`.

Свободная практика `/context` допускает любую уместную формулировку.
Если задание просит применить определённую фразу, она прямо указана в условии.
Оба вида практики не изменяют интервалы повторения слов.

`/quick` открывает отдельную пятиминутную сессию только с вариантами ответа.
Направления немецкий → русский и русский → немецкий чередуются. Сначала идут
новые слова, затем карточки по возрастанию SRS-этапа; после полного прохода
начинается новый круг. Новое или уже подошедшее к повторению слово обновляет
SRS. Досрочный ответ остаётся в истории задания и счётчиках сессии, но не меняет
`progress` и не создаёт `review`.

`/reminders` хранит настройки отдельно для каждого ученика. Режим `Smart`
задаёт разрешённые дни, локальное временное окно и минимальный интервал между
сообщениями. Curator выбирает полезные моменты внутри этих границ и может писать
реже; при его недоступности действует due-only deterministic fallback. `Off`
отменяет будущие напоминания. Telegram не получает доступ к глобальным jobs.

После ответа под вердиктом появляются действия `В архив` и `Ошибка`. Архивация
требует подтверждения. `Ошибка` сразу помечает карточку как `needs_fix` и
исключает её из всех тренировок, затем запрашивает описание ошибки одним
сообщением. Комментарий и ссылка на упражнение сохраняются в
`needs_fix_reason` и `needs_fix_task_id`; список доступен через `/issues`.
Даже без комментария карточка остаётся исключённой. Бот не исправляет её:
пометки разбираются отдельно агентом.

После исправления агент может вызвать `vocab.words.replace_word_card(database,
user_id, word_id, fields)`: функция валидирует новую карточку, возвращает статус
`active`, снимает пометку и делает карточку доступной для повторения.
До замены нужно прочитать и сохранить пометку в отчёте разбора, поскольку
эта функция очищает поля `needs_fix_*`.

Каждая карточка содержит непустой пример употребления. После завершённого
ответа бот показывает вариант ответа и пример; в новых контекстах — пример
для конкретного задания.

Когда Tutor предлагает новые карточки, он может выбрать только уже существующую
неархивную колоду. Подтверждение добавляет слова в показанную колоду и никогда
не создаёт новую автоматически. Новые колоды создаются явно через
`cli.py deck create`; удалить можно только пустую обычную колоду.

## Менеджерский CLI

CLI управляет данными и фоновыми jobs, но не запускает тренировки и не оценивает
ответы. Все команды возвращают JSON и принимают глобальный `--user` (по
умолчанию `owner`) и `--database-url`:

```bash
uv run python cli.py sync
uv run python cli.py deck list
uv run python cli.py deck create B1.1
uv run python cli.py stats --deck A2
uv run python cli.py issues
uv run python cli.py word-archive <word_id>
uv run python cli.py word-restore <word_id> --deck A2
uv run python cli.py word-flag <word_id> --reason "ошибка перевода"
uv run python cli.py word-fix <word_id> --card-json '{...}'
uv run python cli.py job list
uv run python cli.py job run push
```

`job run` только сохраняет запрос. Его забирает и выполняет живой процесс бота;
для отключённой job требуется `--force`.

Полный перечень: `uv run python cli.py --help`.

## Проверка и эксплуатация

```bash
UV_CACHE_DIR=/private/tmp/words-trainer-uv-cache \
  uv run python -m unittest discover -s tests -v
scripts/ops_check.sh
scripts/backup_postgres.sh
```

LaunchAgent-файлы находятся в `deploy/`. Установка выполняется
`scripts/install_launchd.sh`; восстановление проверяется по
[инструкции](docs/operations.md).

Основные гарантии: одна открытая задача и сессия на ученика, атомарная оценка и
действия с карточкой, изоляция по ученику и языку, сохранение истории при
архивации, локальные календарные дни в статистике, подтверждение AI-карточек
перед записью, лимит расходов OpenAI и persisted claims против повторных
push-сообщений и jobs. План напоминаний хранится в PostgreSQL, повторно
проверяется непосредственно перед отправкой и учитывает revision, timezone,
окно, minimum gap, активную длинную сессию, недавнюю практику и наличие due-слов.
